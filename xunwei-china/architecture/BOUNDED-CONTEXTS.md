> **阶段**：0→1 T0–T1 MVP  
> **原则**：单体优先，模块边界用**显式契约**定义，不急于微服务化  
> **映射依据**：产品全案 §5 产品设计方案 + §6 数据方案 + 基线清单 §8 二维准入表

## 上下文详情

### C1 · 菜品知识库（Dish Knowledge）

| 字段 | 值 |
|------|-----|
| **责任** | 管理菜品、食材、技法、菜系的结构化数据 |
| **模型/语言** | 领域实体：Dish（菜品）、Ingredient（食材）、Technique（技法）、Cuisine（菜系）、Source（数据源） |
| **邻接** | C2 地理编码、C3 推荐引擎、C8 数据接入 |
| **关系** | ↗ C2 共享内核（地理编码）→ C3 客户-供应商（推荐引擎读菜品数据）← C8 客户-供应商（数据接入写菜品数据） |
| **翻译面** | 外部数据源（开源 ETL）的字段映射 → 内部 Dish 实体。**翻译层必须记录每个字段的源数据来源和许可证** |

**关键不变量**：
- 每条菜品记录必须有数据源标注（`source_name` + `source_license` + `verified_at`）
- 过敏原字段缺失时，必须显式标注为"未收录"，而不是空值
- `locality_score` 计算必须用 S0 权重表（60/25/15），不允许内联计算

---

### C2 · 地理编码（Geo Code）

| 字段 | 值 |
|------|-----|
| **责任** | 管理行政区划、地理粒度、地理归属判定 |
| **模型/语言** | GeoEntity（行政单元：省/市/区县/街道）、GeoBoundary（地理边界）、LocalityMapping（地域归属映射） |
| **邻接** | C1 菜品知识库、C3 推荐引擎 |
| **关系** | ← C1 共享内核（地理编码枚举表共用）→ C3 客户-供应商（推荐引擎做地理粒度查询） |
| **翻译面** | 外部地理数据源（如行政区划库）→ 内部 GeoEntity。**翻译必须记录许可证** |

**关键不变量**：
- 菜品的地理归属必须能追溯到 GeoEntity
- 多地域归属的菜品（如"争议菜品"）→ 用 GeoConflict 标注，不做单一断言

---

### C3 · 推荐引擎（Recommendation）— 核心

| 字段 | 值 |
|------|-----|
| **责任** | 二维准入 + 安全硬过滤 + 单标量排序 + 展示层组装 |
| **模型/语言** | 四个内部模型（分层定义）：<br>① Adjudication（准入判定：二维准入表）<br>② SafetyGate（安全过滤：过敏原/忌口/幻觉）<br>③ Scoring（排序计算：locality_score）<br>④ PresentationRule（展示规则：四象限矩阵） |
| **邻接** | C1 菜品知识库（读菜品数据）、C2 地理编码（读地理粒度）、C4 AI 推荐（被 AI 复用）、C5 用户画像（读用户约束） |
| **关系** | ← C1/C2 客户-供应商（只读依赖）← C5 客户-供应商（只读用户画像）→ C4 客户-供应商（AI 复用推荐引擎） |
| **翻译面** | **这是系统的核心翻译面**。用户的自然语言/搜索词 → 结构化约束 → 推荐结果 + 展示标签。翻译必须**显式记录每一层的判定理由** |

**关键不变量**（架构级）：
1. 准入层使用二维条件，排序层使用单标量 —— **两层严格解耦**
2. 安全硬过滤在召回层（候选集形成前），而非排序层
3. `evidence_strength` 只影响展示标签，**不参与降权**
4. 🔴+高本地性条目**不折叠、不降权**（四象限规则）
5. 推荐接口必须**显式输出每一层的判定结果**（调试日志）

---

### C4 · AI 推荐（AI Assistant）

| 字段 | 值 |
|------|-----|
| **责任** | 约束提取、RAG 证据检索、诚实层、格式化生成 |
| **模型/语言** | StructuredConstraint（结构化约束）、EvidenceChain（证据链：来源+核验时间）、HonestyDeclaration（诚实声明：能力档位） |
| **邻接** | C3 推荐引擎（复用推荐）、C5 用户画像（读画像）、C1 菜品知识库（读知识） |
| **关系** | → C3 客户-供应商（AI 不做推荐计算，只调用推荐引擎）← C5/C1 客户-供应商（只读） |
| **翻译面** | 用户自然语言 → StructuredConstraint。**翻译不输出推荐，只输出约束** |

**关键不变量**：
1. AI 不直接生成菜品描述 —— 只做结构化填充与数据关联
2. AI 回答必须附：推荐依据（五要素）、数据源、核验时间、能力档位声明
3. 不确定时明确说"资料不足，建议电话确认" —— **不编造**
4. AI 不接收任何商业导流信号 —— 物理隔离

**Anti-Corruption Layer（ACL）**：AI 不直接操作 PostgreSQL，通过 RAG（向量库检索）+ C3 推荐引擎获取数据。这是一个显式的 ACL，防止 LLM 幻觉污染数据源。

---

### C5 · 用户画像（User Profile）

| 字段 | 值 |
|------|-----|
| **责任** | 管理用户口味偏好、忌口过敏档案、家庭档案、历史决策 |
| **模型/语言** | UserPreference（口味偏好标签）、DietaryRestriction（忌口/过敏 —— **敏感数据**）、FamilyProfile（家庭多人档案合并）、DecisionHistory（历史决策） |
| **邻接** | C3 推荐引擎（被读）、C4 AI 推荐（被读）、C6 行为分析（被写） |
| **关系** | ← C6 客户-供应商（行为事件驱动画像更新）→ C3/C4 客户-供应商（只读被查询） |
| **翻译面** | 行为事件 → 画像更新信号。**翻译必须异步，不能阻塞主流程** |

**关键不变量**：
1. 忌口/过敏数据默认本地存储 —— 不上传到服务器，除非用户显式授权
2. 一键清除所有画像数据功能（合规要求）
3. 家庭档案合并时，冲突口味走结构化处理（不做 LLM 判断）

---

### C6 · 行为分析（Behavior Analytics）

| 字段 | 值 |
|------|-----|
| **责任** | 埋点数据收集、实时画像更新、指标计算（WDCU 等） |
| **模型/语言** | Event（行为事件：`dish_detail_view`、`menu_add`、`chat_decide` 等）、MetricSnapshot（指标快照） |
| **邻接** | C5 用户画像（写画像） |
| **关系** | → C5 客户-供应商（异步写画像） |
| **翻译面** | 原始埋点事件 → 画像更新信号 + 指标。**翻译必须异步、幂等、可重放** |

**关键不变量**：
1. 埋点事件必须**不阻塞主请求**（fire-and-forget）
2. 丢包率监控 ≤ 1%
3. 指标计算必须**显式声明统计范围和聚合方式**（基线清单 §12 方法论纪律 H12+H13）

---

### C7 · 数据接入（Data Ingestion）

| 字段 | 值 |
|------|-----|
| **责任** | 开源数据 ETL、许可证审计、数据版本化 |
| **模型/语言** | DataSource（数据源 + 许可证）、ETLJob（ETL 任务 + 版本） |
| **邻接** | C1 菜品知识库（写菜品数据）、C2 地理编码（写地理数据） |
| **关系** | → C1/C2 客户-供应商（离线批量写） |
| **翻译面** | 外部数据源 → 内部模型。**翻译必须记录许可证和版本** |

**关键不变量**：
1. 许可证必须审计通过才能入库
2. 每次 ETL 必须产生数据版本快照
3. **不自建数据采集**（T0 W1 铁律 —— 基线清单）

---

### C8 · 商业导流（Commercial Funnel）— T3 启用

| 字段 | 值 |
|------|-----|
| **责任** | 外部跳转、佣金追踪、商业化分析 |
| **模型/语言** | PartnerLink（外部跳转链接）、FunnelEvent（导流事件） |
| **邻接** | 外部地图/点评 |
| **关系** | 物理隔离，不与 C3/C4 任何上下文通信 |
| **翻译面** | 内部跳转请求 → 外部链接 + 追踪参数 |

**关键不变量**：
1. **物理隔离** —— 推荐层（C3/C4）和导流层（C8）物理隔离，不共享任何进程/服务
2. 推荐层不接收任何付费信号
3. 用户可感知的"不看推广"开关
