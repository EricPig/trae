# ADR-001 · 系统总览与核心架构决策

> **状态**：Proposed（基于产品全案 v1.2 + 基线清单 v3.1 推导）  
> **阶段**：0→1 立项 → T0 验证  
> **裁决来源**：产品全案 §1.2 核心模型、§1.5 十个必须知道的裁决；基线清单 §7 回归断言、§8 二维准入表  
> **责任角色**：架构师（当前推导为 user + 本地检查路径）

---

## 1. 决策问题

**如何在"可核验的裁决"这一产品定位下，设计一个既能保护差异化护城河（隐藏款/资料稀疏老店）又能满足安全红线（过敏原违反率=0）的推荐架构？**

这个问题的根本矛盾是：
- 降权会直接抹杀差异化（🔴+高本地性=隐藏款保护对象，降权=自杀）
- 不降权会让"资料不全"的条目混入排序，降低用户信任
- 单标量排序无法同时满足"隐藏款保护"和"连锁淘汰"两个目标

---

## 2. Forces（驱动力）

| # | Force | 来源 | 理由 |
|---|-------|------|------|
| F1 | **隐藏款保护是唯一差异化** | 全案 §1.5 裁决 1、§1.6 指标反噬 | 🔴+高本地性条目若被降权，等于复制探饭失败路径（对小众商户覆盖不足） |
| F2 | **两条安全红线必须硬约束** | 全案 §1.3 关键数字速览、§2.5 分层指标护栏 | 过敏原违反率=0、门店事实幻觉率=0 —— 一票否决，无弹性 |
| F3 | **单标量方案 861 组不可行** | 基线清单 §8 | Pareto 穷举证明单标量同时满足"准入率 ≤88% + 交叉反转率 ≤12%"无可行解 |
| F4 | **用户信任源于"有来源"而非"更准"** | 全案 §3.9 AI 态度、N1–N7 | 用户不信任 AI 编造，信"诚实的不知道"和"可核验的证据链" |
| F5 | **AI 推荐响应 P95 ≤1.2s** | 全案 §2.5 护栏 | 对话收敛轮次 ≤4 轮，单轮延迟预算必须严格 |
| F6 | **AI 成本受控** | 全案 §1.3 总成本 166.5 万、§6 数据方案 | T1 MVP 阶段预算有限，LLM 调用必须有缓存和降级策略 |
| F7 | **商业导流不污染推荐** | 全案 §1.5 裁决 8、N2 | 推荐层不接收付费排名；导流与推荐物理隔离 |

## 3. Alternatives（备选方案）

### ✅ 方案 A：二维准入 + 单标量排序 + 分阶段硬过滤（**采纳**）

```
┌─────────────────────────────────────────────────────────────┐
│  输入：菜品数据（含 locality_score + evidence_strength）      │
├─────────────────────────────────────────────────────────────┤
│  ① 二维准入层（精细筛选）                                    │
│     ├─ native（A/B/C/D）→ threshold 60                      │
│     ├─ localized（A/B）→ threshold 60                       │
│     ├─ localized C → threshold 55 + UI 提示                 │
│     ├─ localized D → threshold 50 + UI 提示                 │
│     └─ national_chain → 排除                               │
├─────────────────────────────────────────────────────────────┤
│  ② 安全硬过滤层（一票否决）                                  │
│     ├─ 过敏原/忌口 → 命中即排除（召回层）                    │
│     ├─ 幻觉风险 → 无数据源支撑即排除                         │
│     └─ 覆盖外 → 诚实降级 + 提示                              │
├─────────────────────────────────────────────────────────────┤
│  ③ 单标量排序层（locality_score 主因子）                     │
│     └─ evidence_strength 参与展示标签，不参与降权           │
├─────────────────────────────────────────────────────────────┤
│  ④ 展示层（四象限规则矩阵）                                  │
│     ├─ 🟢+高本地性 → 最佳推荐位                              │
│     ├─ 🟡+高本地性 → 重点扶持位                              │
│     ├─ 🔴+高本地性 → 禁降权禁折叠必优先（护城河）            │
│     └─ 🔴+低本地性 → 唯一允许折叠的象限                     │
└─────────────────────────────────────────────────────────────┘
```

**理由**：基线清单 §8 已证明这是唯一可行解。准入层用二维条件实现精细筛选力（82.4% 准入率 + 7.6% 交叉反转率），排序层用单标量避免副作用。结构分离完美契合基线清单 §8 项目级设计原则："当两个问题的最优解冲突时，不要在参数里找折中，而要在结构上分开它们。"

### ❌ 方案 B：单标量映射调至 85

**拒绝理由**：交叉反转率 24.4% —— 资料稀疏老店被地方变体反超，直接违反"隐藏款保护"（Force F1）。基线清单已实测证伪。

### ❌ 方案 C：单标量阈值调至 50

**拒绝理由**：准入率 89.7% —— 筛选力形同虚设。基线清单已实测证伪。

### ❌ 方案 D：硬编码"连锁直接 0 分"

**拒绝理由**：与"项目级设计原则"（基线清单 §8）冲突。861 组穷举的问题本质是"准入"和"排序"耦合，不是"连锁不连锁"。过度粗糙的规则会让 `localized` 类型（本地连锁）也被误杀。

### ❌ 方案 E：R4 独立于主推荐流

**拒绝理由**：基线清单 §4.3 已裁决"R4 独立上线门禁 —— 架构保证 + 静态链路验证 + 理解度 ≥80%，不等 63 天 AB"。但独立推荐流 = 架构重复 + 数据分裂 + 用户体验分裂。正确解是**在召回层加入过敏原硬过滤**（同一推荐流内），而非物理隔离。

---

## 4. Decision

### 核心决策 1：两层分离架构

> **准入层**用二维条件（`locality_level` × `cuisine_evidence_level` + 不同阈值），**排序层**用单标量 `locality_score`（60/25/15 权重表：0.60×native + 0.25×years_factor + 0.15×cuisine_factor）。

- 准入层只做"是否进候选池"的判定，不做排序
- 排序层只做"候选池内的相对位置"，不做准入判定
- **两层严格解耦**：准入条件变化不影响排序权重，排序权重变化不影响准入条件

### 核心决策 2：安全硬过滤在召回层

> 过敏原/忌口过滤 = **召回层硬约束**（不进入候选集），而非排序降权。

- 排序层看不到过敏原约束，只看到"候选集已经被过滤过"
- 过敏原字段缺失的条目 = 自动归入"信息不完备" → 诚实降级
- 门店事实幻觉风险 = 无数据源支撑的条目 → 召回层直接排除

### 核心决策 3：展示层四象限规则

> `evidence_strength` 只影响**展示标签**（徽标 + ⓘ），不影响排序权重。🔴 条目一律不折叠、不降权。

### 核心决策 4：AI 推荐架构 —— "诚实优先"

> AI 只做 **结构化填充 + 数据关联**，不直接生成菜品描述。AI 回答必须附：推荐依据（五要素）、数据源、核验时间、能力档位声明。

- 不确定时明确说"资料不足，建议电话确认" —— 不编造
- 多轮对话收敛轮次 ≤ 4 —— 超时或条件不足即升级或降级
- 商业导流与推荐物理隔离（推荐服务不接收任何付费信号）

## 5. Consequences

### Positive（正向）

| # | 后果 | 支撑的 Force |
|---|------|-------------|
| C+1 | 隐藏款保护有了结构级保证（不是参数调优） | F1 |
| C+2 | 安全红线变成架构不变量（召回层过滤） | F2 |
| C+3 | 准入层和排序层可以独立演进（二维表参数可调不影响排序，反之亦然） | F3（长期可维护） |
| C+4 | 诚实 AI 叙事有了技术实现路径（附依据、承认不确定） | F4 |
| C+5 | AI 响应延迟可控（推荐不依赖 LLM 生成，只做检索和排序） | F5 |

### Negative（负向）

| # | 后果 | 缓解措施 |
|---|------|---------|
| C−1 | 两层分离增加了调试复杂度（为什么某条目不显示？先查准入，再查排序，再查安全过滤） | 推荐链路日志必须**显式记录每一层的判定结果**（准入判定 + 排序得分 + 安全过滤状态） |
| C−2 | 基线清单 §24 警告："聚合值掩盖了分层差距"（D 级 17.1% 超标 vs 聚合 9.2% 通过） | 监控看板**必须同时展示分层值和聚合值**，绝不允许只看聚合 |
| C−3 | AI 不生成菜品描述 = MVP 阶段内容完整度依赖人工/开源数据源 | T0 W4 必须启动 E7 影子实验（63 天硬约束），验证开源数据可得性 |
| C−4 | 推荐层与导流层物理隔离 = 商业化变现链路更长 | T3 阶段才启动导流验证，不纳入 T1 MVP 架构 |

## 6. Reversibility（可逆性）

| 决策 | 可逆性 | 成本 | 重审触发条件 |
|------|--------|------|-------------|
| 两层分离架构 | **低**（硬编码在核心数据模型和服务边界） | 重构成本 ≈ 重写推荐链路 30–40% | Gate 1 判定"用户不关心隐藏款保护"（H1/H2 失败） |
| 安全硬过滤在召回层 | **极低**（安全红线不能妥协） | **不可逆转** | 无（红线=0 是不可协商的架构不变量） |
| 展示层四象限规则 | **中**（UI 规则可调整） | 重写展示层 + 重新训练用户预期 | Gate 5 判定"🔴+高本地性用户反馈真的不想优先看" |
| AI 不撰写菜品描述 | **中**（AI 功能可追加） | 新增 LLM 生成模块 + 幻觉检测 | T2 后验证"结构化内容对用户来说不够丰富" |

## 7. Responsibility

| 领域 | 负责角色 | 本地检查路径 |
|------|---------|-------------|
| 准入层规则调整 | 产品 + 数据联合裁决 | 必须跑 `data_plan/data_metrics_calc_exp.py` 验证准入率 + 交叉反转率 |
| 排序层权重调整 | 数据 + 算法团队 | 必须跑 `s0_weight_verify.py` + 回归断言 R1–R5 |
| 安全红线变更 | 架构师 + 法务 | **不允许变更**（过敏原违反率=0 是架构级常量） |
| AI 诚实性实现 | AI/ML 团队 | 必须通过 llm-evaluation 框架验证（另开 ADR） |
| 架构整体演进 | 架构师 | 每季度架构评审 + 技术债扫描 |
