## 2. 核心数据流

### 2.1 推荐查询主路径（同步，P95 ≤ 1.2s）

```
用户搜索 "成都+素食+本地人"
        │
        ▼
┌─────────────────┐
│ 1. 准入层判定    │  PostgreSQL → 二维准入表 → candidate_ids
│ (Redis 缓存命中) │  Redis HIT → 1ms；MISS → 查询 PostgreSQL → 5ms + 回写缓存
└────────┬────────┘
         │ candidate_ids (已通过二维准入)
         ▼
┌─────────────────┐
│ 2. 安全硬过滤    │  召回层硬约束（过敏原/忌口/幻觉风险）
│                 │  无过敏原数据的菜品 → 诚实降级
└────────┬────────┘
         │ filtered_ids (安全候选集)
         ▼
┌─────────────────┐
│ 3. 排序层计算    │  locality_score 单标量（60/25/15 权重）
│ (Redis 缓存)     │  排序结果 + 四象限展示标签
└────────┬────────┘
         │ ranked_results
         ▼
┌─────────────────┐
│ 4. 展示层组装    │  四象限规则 → 卡片 UI 数据
│                 │  🟢+高本地性 → 最佳位
│                 │  🔴+高本地性 → 禁降权禁折叠
└────────┬────────┘
         │
         ▼
    HTTP Response (P95 ≤ 1.2s)
```

### 2.2 AI 对话路径（同步 + 可降级，收敛 ≤ 4 轮）

```
用户对话 "我在成都，想找本地人常去的"
        │
        ▼
┌─────────────────────────────────────┐
│ LLM 理解层                            │
│ 提取结构化约束: {city:成都, 偏好:本地} │
│ 不输出推荐，只输出约束条件             │
└────────────┬────────────────────────┘
             │
             ▼
┌─────────────────────────────────────┐
│ 推荐引擎（复用主路径）                │
│ 约束条件 → 二维准入 → 安全过滤 → 排序  │
└────────────┬────────────────────────┘
             │
             ▼
┌─────────────────────────────────────┐
│ AI 诚实层（RAG）                      │
│ 1. 从向量库检索候选的证据链            │
│ 2. 若候选不足 → 诚实告知覆盖不足       │
│ 3. 若有不确定的信息 → 标注"资料不足"    │
│ 4. 组装回答: 推荐 + 依据 + 数据源 + 时间 │
└────────────┬────────────────────────┘
             │
             ▼
┌─────────────────────────────────────┐
│ LLM 生成层                            │
│ 只做格式化，不生成新内容               │
│ 输出: 菜单风格，不生成菜品描述          │
└────────────┬────────────────────────┘
             │
             ▼
    HTTP Response
```

### 2.3 行为埋点路径（异步，不阻塞主请求）

```
用户行为 → 前端埋点 SDK → /api/event（异步 fire-and-forget）
                              │
                              ▼
                    消息队列（Redis Stream 或 Kafka）
                              │
                              ▼
                    实时消费 → 画像服务更新
                              │
                              ▼
                    批量写入 → 行为分析库（OLAP）
```

> **关键约束**：埋点不阻塞主请求。SDK 必须支持 `navigator.sendBeacon`，禁止拦截或重试阻塞用户操作。

## 3. 信任边界

| # | 边界 | 性质 | 数据流向 | 防护措施 |
|---|------|------|---------|---------|
| B1 | 用户浏览器 ↔ 边缘层 | 互联网公网 | 双向 | WAF + Bot Detection + TLS 强制 + 速率限制 |
| B2 | 边缘层 ↔ API 网关 | 内部网络 | 双向 | mTLS + IP 白名单 |
| B3 | API 网关 ↔ 推荐引擎 | 模块间调用 | 单向（网关→引擎） | 内部接口 + 熔断降级 |
| B4 | 推荐引擎 ↔ 数据存储 | 内部 | 单向（引擎→存储读） | 只读连接池 + 查询超时 500ms |
| B5 | AI 推荐 ↔ 数据存储 | 内部 | 单向（AI→存储读） | 同上 + LLM 调用不直接连 DB |
| B6 | 用户画像 ↔ 行为事件流 | 内部 | 单向（事件→画像写） | 异步队列 + 幂等消费 |
| B7 | 外部数据源 → PostgreSQL | 离线集成 | 单向（外部→内部只读 ETL） | 开源许可证审计 + 数据隔离 |
| B8 | 用户浏览器 ↔ 画像数据 | **敏感边界** | 仅前端→后端提交 | 健康/忌口数据本地存储优先 + 显式授权 + 一键清除 |
| B9 | 推荐层 ↔ 导流层 | **严格隔离** | 物理隔离（不同模块） | 推荐服务不接收任何付费信号；导流层独立部署 |

## 4. 失败域（Failure Domains）

### 4.1 失败域定义与影响

| 失败域 | 包含模块 | 失败类型 | 用户影响 | 容错策略 |
|--------|---------|---------|---------|---------|
| **F0 边缘层** | CDN + WAF + Bot | DDoS / 静态资源不可用 | 全站不可访问 | 多 CDN + 源站备份 |
| **F1 API 网关** | Web Framework | 进程崩溃 / 数据库连接池耗尽 | API 全部失败 | 多实例 + 健康检查 + 自动重启 |
| **F2 推荐引擎** | 准入 + 排序 + 缓存 | Redis 故障 / PostgreSQL 慢查询 | 推荐结果不可用 | **降级为直接 PostgreSQL 查询**（延迟从 5ms 升到 50ms，可接受） |
| **F3 安全过滤** | 过敏原过滤 | 过滤逻辑 bug / 数据源缺失 | **安全红线风险** | 静态链路验证（编译期检查）+ 发布前强制测试 |
| **F4 AI 推荐** | LLM + RAG + 诚实层 | LLM 服务不可用 / 幻觉 | AI 功能不可用 | **降级为非 AI 推荐（复用 F2 推荐引擎）**，提示"AI 暂时不可用" |
| **F5 数据存储** | PostgreSQL + Redis + Vector | 存储故障 / 数据损坏 | 核心数据不可用 | WAL 备份 + Redis 持久化 + 只读副本 |
| **F6 画像服务** | 用户 + 家庭档案 | 画像计算错误 | 推荐不准确 | 画像计算异步 + 快照版本 + 可回滚 |
| **F7 行为埋点** | SDK + 事件流 | 消息队列故障 | 数据丢失 | 本地缓存 + 重试 + 丢包率监控（≤1%） |
| **F8 外部数据源** | 开源 ETL | 数据源不可达 / 许可证变更 | 数据不更新 | 定期快照 + 许可证审计 + 数据版本化 |

### 4.2 失败级联防护

```
用户查询 → API 网关 → 推荐引擎 ──→ PostgreSQL（降级：缓存 MISS 直查）
                   │                    │
                   └── Redis（失败→旁路） └── Vector Store（RAG 失败→降级为结构化搜索）
                   │
                   └── AI 推荐（失败→降级为非 AI 推荐）
```

**关键原则**：F2（推荐引擎）和 F4（AI 推荐）必须能**独立降级**。推荐引擎不能依赖 AI，AI 也不能阻塞推荐引擎。

### 4.3 安全红线失败域（特别关注）

> 这是**架构级不变量**，不是"可恢复的失败"。过敏原违反率和门店事实幻觉率必须在发布前为 0。

| 防护层 | 机制 | 触发 | 响应 |
|--------|------|------|------|
| 发布前静态检查 | 编译期验证过敏原过滤链路完整性 | 每次 CI | 红灯 → 禁止合并 |
| 发布前动态测试 | Gate 5 理解度测试（≥80% 通过） | 每次发布 | 红灯 → 禁止发布 |
| 运行时监控 | 每日自动扫描推荐结果是否含过敏原违反 | 每日 | 发现即报警 + 自动回滚 |
| 事后追踪 | 每次推荐请求的安全过滤判定可审计 | 实时 | 异常请求标记为危险，自动降级 |

## 5. 交互风格决策（Interaction Style）

| 路径 | 风格 | 理由 | 替代方案 |
|------|------|------|---------|
| 推荐查询 | **同步请求/响应** | P95 ≤ 1.2s，用户等得起 | ❌ 异步推送：推荐结果时效要求高，推送会引入延迟和复杂状态管理 |
| AI 对话 | **同步多轮** | 收敛 ≤ 4 轮，单轮延迟可接受 | ❌ 流式 SSE：MVP 阶段 LLM 延迟不稳定，先保证可用性 |
| 行为埋点 | **异步 fire-and-forget** | 不阻塞主请求 | ❌ 同步：用户流失率会提升；❌ 批量轮询：实时性差 |
| 推荐缓存 | **本地读-through + 后台刷新** | Redis 毫秒级；缓存失效时直查 DB | ❌ 本地投影：首次冷启动无数据，且投影维护成本高 |
| 数据 ETL | **批量定时 + 增量 CDC** | 开源数据低频更新（周/月），实时性要求低 | ❌ 实时流处理：复杂度高且不需要 |
| 画像更新 | **异步事件驱动** | 画像计算不阻塞推荐 | ❌ 同步：每次推荐都计算画像会导致延迟超标 |
