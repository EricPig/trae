# 适应度函数（Fitness Functions）

> **Iron Law**：每条适应度函数必须可测量、有阈值、有评估周期、有失败响应。"应该快"或"应该准确"都是不合格的条目。  
> **来源**：产品全案 §1.2 核心模型、§2.5 分层指标、§6 数据方案 + 基线清单 §7 回归断言、§8 二维准入表  
> **架构不变量**：系统依赖这些属性正确运行，任何一条被破坏都意味着架构被违反。

---

## 1. 准入层不变量

### FF-ADJ-01 · 准入率约束

| 字段 | 值 |
|------|-----|
| **被测属性** | 二维准入表的总体准入率不超过 88%（保证有筛选力） |
| **指标** | `admission_rate = 准入条目数 / 总条目数 × 100` |
| **阈值/规则** | ≤ 88%（实测基线 82.4%） |
| **测量源** | PostgreSQL 查询 `SELECT COUNT(*) FROM dishes WHERE admission_result = 'admitted'` |
| **评估周期** | 每次准入层参数变更（pre-commit + CI） |
| **失败响应** | CI 红灯 → 禁止合并 |
| **本地检查路径** | `data_plan/data_metrics_calc_exp.py` |

### FF-ADJ-02 · 交叉反转率约束

| 字段 | 值 |
|------|-----|
| **被测属性** | 二维准入表不违背隐藏款保护（资料稀疏老店不被降权反超） |
| **指标** | `cross_reversal_rate = 被地方变体反超的 native+D 条目数 / native+D 总条目数 × 100` |
| **阈值/规则** | ≤ 12%（实测基线 7.6%） |
| **测量源** | PostgreSQL 联合查询 + 排序对比 |
| **评估周期** | 每次准入层参数变更 |
| **失败响应** | CI 红灯 → 禁止合并 |
| **本地检查路径** | `data_plan/data_metrics_calc_exp.py` |

### FF-ADJ-03 · 连锁最高分约束

| 字段 | 值 |
|------|-----|
| **被测属性** | 连锁菜品不得进入推荐位 |
| **指标** | `national_chain_max_score` |
| **阈值/规则** | < 50.0（实测最高分 40.0） |
| **测量源** | `MAX(locality_score) WHERE locality_level = 'national_chain'` |
| **评估周期** | 每次排序权重变更 + 每日自动扫描 |
| **失败响应** | CI 红灯 + 生产报警 |
| **本地检查路径** | `s0_weight_verify.py` |

## 2. 排序层不变量

### FF-SCR-01 · native 最低分约束

| 字段 | 值 |
|------|-----|
| **被测属性** | native 类型的菜品 locality_score 恒 ≥ 60（不被年限或证据等级压垮） |
| **指标** | `MIN(locality_score) WHERE locality_level = 'native'` |
| **阈值/规则** | ≥ 60.0（实测最低 60.0，恒成立） |
| **测量源** | PostgreSQL 查询 |
| **评估周期** | 每次排序权重变更 + 每日自动扫描 |
| **失败响应** | CI 红灯 + 生产报警 |
| **本地检查路径** | `s0_weight_verify.py` |

### FF-SCR-02 · native+D 级被压过率分层监控

| 字段 | 值 |
|------|-----|
| **被测属性** | 聚合值不掩盖分层差距 |
| **指标** | 分层值 + 聚合值同时监控 |
| **阈值/规则** | 
| | 3a（≥20 年）≤ 12%（主判据）|
| | 3b（<20 年）≤ 40.4%（记录不阻塞）|
| | 3c（全量）≤ 9.2%（上界断言）|
| | **D 级 ≤ 12%**（FF 单独监控，聚合值掩盖不了）|
| **测量源** | PostgreSQL 分层查询 |
| **评估周期** | 每周看板 + 每次排序权重变更 |
| **失败响应** | D 级 > 17.1% → T1 触发次级因子加权 |
| **本地检查路径** | `criterion_final.py` |

### FF-SCR-03 · 超老连锁越线年份

| 字段 | 值 |
|------|-----|
| **被测属性** | 92–94 年连锁不被误判为安全（最贴近阈值的边界） |
| **指标** | `first_breach_year` |
| **阈值/规则** | ≥ 92（实测 92 年，91=59.375 / 92=60.0 / 93=60.625）|
| **测量源** | `s0_weight_arbitration.py` 脚本输出 |
| **评估周期** | 每次排序权重变更 |
| **失败响应** | CI 红灯 → 禁止合并 |
| **本地检查路径** | `s0_weight_arbitration.py` |

## 3. 安全红线不变量（架构级常量）

### FF-SAFE-01 · 过敏原违反率

| 字段 | 值 |
|------|-----|
| **被测属性** | 有明确忌口/过敏的用户，其推荐结果中**绝不应出现**对应过敏原 |
| **指标** | `allergen_violation_rate` |
| **阈值/规则** | **= 0%**（一票否决，无弹性）|
| **测量源** | 
| | ① 发布前：自动化测试（覆盖所有过敏原类型 × 所有菜品 × 所有用户画像组合）|
| | ② 运行时：每日自动扫描（抽样 1000 条推荐请求，检查是否有过敏原违反）|
| **评估周期** | 每次发布 + 每日自动扫描 + 每月全面回归 |
| **失败响应** | ① CI 红灯 → 禁止发布；② 生产扫描发现 → 自动回滚 + 紧急修复 |
| **本地检查路径** | Gate 5 测试套件（T5） |

### FF-SAFE-02 · 门店事实幻觉率

| 字段 | 值 |
|------|-----|
| **被测属性** | AI 推荐的菜品/门店，所有事实性陈述必须有数据源支撑 |
| **指标** | `hallucination_rate` |
| **阈值/规则** | **= 0%**（一票否决）|
| **测量源** | 
| | ① 发布前：RAG 检索覆盖率测试（每个推荐结果必须有 ≥1 个数据源引用）|
| | ② 运行时：审计抽样（每日 100 条 AI 推荐，检查每条的数据源完整性）|
| **评估周期** | 每次 AI 模块发布 + 每日审计抽样 |
| **失败响应** | CI 红灯 → 禁止发布 + 运行时发现即降级 AI 功能 |
| **本地检查路径** | llm-evaluation 框架（另开 ADR） |

### FF-SAFE-03 · 过敏原信息完备度

| 字段 | 值 |
|------|-----|
| **被测属性** | 含常见过敏原的菜品，其过敏原字段不能缺失 |
| **指标** | `allergen_field_completeness_rate` |
| **阈值/规则** | ≥ 95%（首批 5 省）|
| **测量源** | `SELECT COUNT(*) FROM dishes WHERE has_common_allergen = true AND allergen_info IS NULL` |
| **评估周期** | 每周看板 + 每次数据接入 |
| **失败响应** | 优先级：补数据优先于补功能 |
| **本地检查路径** | 数据质量仪表盘 |

## 4. 性能与延迟不变量

### FF-PERF-01 · 推荐接口 P95

| 字段 | 值 |
|------|-----|
| **被测属性** | 推荐查询接口端到端延迟 |
| **指标** | API Gateway → HTTP Response 的 P95 延迟 |
| **阈值/规则** | ≤ 1.2s |
| **测量源** | 分布式追踪（OpenTelemetry）|
| **评估周期** | 生产监控（实时）+ 每次部署后 |
| **失败响应** | P95 > 1.2s 持续 5 分钟 → 报警；P95 > 2.0s 持续 10 分钟 → 自动降级缓存旁路 |

### FF-PERF-02 · LCP 性能

|------|-----|
| **被测属性** | 首次有意义绘制时间（Largest Contentful Paint）|
| **指标** | P75 LCP |
| **阈值/规则** | ≤ 2.5s（3 秒内加载完成）|
| **测量源** | 真实用户监控（RUM）|
| **评估周期** | 每周 RUM 报告 + 每次前端部署 |
| **失败响应** | P75 > 2.5s 持续一周 → 前端性能专项 |
| **本地检查路径** | RUM 看板 |

### FF-PERF-03 · AI 对话收敛轮次

| 字段 | 值 |

| **本地检查路径** | AI 评估看板 |

## 5. 架构解耦不变量

### FF-ARCH-01 · 准入层与排序层解耦

| 字段 | 值 |
|------|-----|
| **被测属性** | 准入条件变化不影响排序权重；排序权重变化不影响准入条件 |
| **指标** | 
| | ① 修改准入阈值后，排序分布不应系统性偏移 |
| | ② 修改排序权重后，准入率不应变化 |
| **阈值/规则** | 修改后变化 ≤ 5%（在可控范围内）|
| **测量源** | 变更前后对比测试 |
| **评估周期** | 每次准入/排序参数变更 |
| **失败响应** | 回滚参数变更 |
| **本地检查路径** | `data_plan/data_metrics_calc_exp.py`（双跑前后对比）|

### FF-ARCH-02 · 证据完备度不参与降权

| 字段 | 值 |
|------|-----|
| **被测属性** | 准入结果为 admitted 的条目，无论 `evidence_strength` 等级如何，排序层不能以它为依据降权 |
| **指标** | 
| | ① 排序层代码中，evidence_strength 变量不应出现在 locality_score 计算中 |
| | ② 🔴 条目的平均排序位置不应系统性低于 🟢 条目（按 locality_score 匹配对比）|
| **阈值/规则** | 无代码引用 + 位置差异 ≤ 10% |
| **测量源** | ① 静态代码分析（grep）；② 排序结果抽样对比 |
| **评估周期** | 每次代码变更（pre-commit）+ 每日自动检查 |
| **失败响应** | CI 红灯 → 禁止合并 |
| **本地检查路径** | 静态代码检查脚本 + 每日排序抽样 |

### FF-ARCH-03 · 推荐层与导流层物理隔离

| 字段 | 值 |
|------|-----|
| **被测属性** | 推荐引擎和 AI 推荐模块**不接收任何商业导流信号** |
| **指标** | 静态代码检查 |
| **阈值/规则** | 
| | ① 推荐引擎代码中不含 `commercial`, `sponsored`, `promotion`, `paid` 等关键词 |
| | ② 推荐查询 API 签名不含任何导流参数 |
| **测量源** | 静态代码扫描 |
| **评估周期** | 每次推荐模块代码变更（pre-commit）+ 每周全量扫描 |
| **失败响应** | CI 红灯 → 禁止合并 |
| **本地检查路径** | 推荐层纯净度扫描脚本 |

### FF-ARCH-04 · AI 不直接生成菜品描述

| 字段 | 值 |
|------|-----|
| **被测属性** | LLM 的输出**不直接作为**菜品描述内容 |
| **指标** | 静态代码 + 运行时审计 |
| **阈值/规则** | 
| | ① 菜品详情页的所有描述文本必须来自 PostgreSQL（结构化字段），不来自 LLM 输出 |
| | ② LLM 输出仅用于：约束提取、RAG 证据链格式化、对话菜单 |
| **测量源** | ① 静态代码扫描；② 运行时审计（每日 100 条 AI 推荐检查）|
| **评估周期** | pre-commit + 每日审计 |
| **失败响应** | CI 红灯 + 运行时发现即降级 |
| **本地检查路径** | AI 输出来源审计脚本 |
